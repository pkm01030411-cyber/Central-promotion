GitHub에 새 저장소를 만듭니다. 기본 브랜치 이름은 `main`으로 사용합니다. 2. 이 폴더 **안의 파일과 폴더 전체**를 저장소 최상위에 업로드하고 커밋합니다. ZIP 파일 자체를 업로드하지 마세요. `index.html`이 저장소 첫 화면에 보여야 합니다. 3. 숨김 폴더인 `.github/workflows/pages.yml`도 포함됐는지 확인합니다. 웹 업로드에서 빠졌다면 **Add file → Create new file**로 해당 경로를 만들고 동봉된 YAML 내용을 붙여 넣습니다. 4. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다. 5. **Actions → Deploy website to GitHub Pages → Run workflow → main**을 실행합니다. 처음 업로드 때 Pages 설정 전이라 실패했다면 설정 후 다시 실행하면 됩니다. 6. 배포가 완료되면 **Settings → Pages** 또는 성공한 Actions 실행의 `github-pages` 링크에서 사이트 주소를 확인합니다. 이후 `main`에 변경사항을 커밋하면 자동으로 다시 배포합니다. 다른 브랜치를 쓰면 `.github/workflows/pages.yml`의 `branches`도 바꾸세요. 일반 프로젝트 사이트의 주소는 `https://사용자명.github.io/저장소명/` 형식입니다. GitHub Free에서는 공개 저장소로 Pages를 사용할 수 있으며, 비공개 저장소 지원은 계정 플랜에 따라 다릅니다. 현재 ChatGPT 사이트의 접근 권한은 GitHub로 옮겨지지 않습니다. ## 파일 구성 - `index.html`: 상품 선택, 할인 전후 가격 비교, 행사 소개 - `visit.html`: 실제 터미널 위치, 가상 매장 배치, 행사 조건 - `styles.css`, `friendly.css`: 반응형 디자인과 모션 - `logic.js`: 상품 가격, 행사 기간, 세트 할인 계산 - `app.js`: 상품 선택, 드래그 담기, 가격 표시 - `common.js`: 페이지 간 조합 유지, 모달, 알림 - `location.js`: 가상 안내도와 교통 안내 - `assets/promotion.webp`: 상품 이미지 - `.github/workflows/pages.yml`: GitHub Pages 자동 배포 - `.nojekyll`: 정적 파일 제공 설정 ## 할인 기준과 수정 위치 밥 메뉴(소불고기덮밥 또는 닭갈비볶음밥) 1개 + 샐러드랩 1개를 한 세트로 20% 할인합니다. 밥끼리·랩끼리는 할인하지 않고, 세트에 포함되지 않은 상품은 정상가입니다. 두 종류의 밥 메뉴가 있으면 가격이 높은 밥 메뉴부터 랩과 짝을 짓습니다. `logic.js`의 `config`에서 상품명·가격·행사 기간·하루 세트 한도를 수정할 수 있습니다. 화면의 고정 문구와 FAQ도 함께 맞춰주세요. 현재 기간은 2026-10-21~2026-11-03, 매일 낮 12시, 하루 최대 20세트입니다. 행사 종료 후에는 담기와 할인 체험이 비활성화됩니다. 선택 내용은 같은 브라우저 탭의 `sessionStorage`에 저장합니다. 로그인·서버·데이터베이스가 필요하지 않습니다. 실제 주문, 수량 예약, 실시간 재고 차감 기능은 없습니다. 건물 위치는 센트럴시티 터미널이지만 매장과 실내 배치도는 가상입니다. ## 로컬 확인 `index.html`을 브라우저로 열면 화면을 확인할 수 있습니다. 페이지 간 선택 유지와 주소 복사까지 확인하려면 로컬 HTTP 서버를 권장합니다.
